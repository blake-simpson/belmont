## Deliberate design notes

- **One overlay, two visible states; focus is the axis.** The
  alternative — render the panel as a `setWidget` line above the
  editor + open a separate `ctx.ui.custom` overlay for navigation —
  duplicates the rendering surface and creates two sources of truth
  for the milestone tree. The single-overlay/two-state model uses
  pi-tui's `OverlayHandle.focus()`/`unfocus()` directly and keeps the
  PanelComponent the only renderer.
- **`setAutoActiveProbe` is the M8 install-point.** M6 always returns
  `false` from the probe, so Ctrl+B from active always closes. M8
  will install a probe that consults the auto loop's `activeAuto`
  state; tests already simulate this (`with autoActive probe
  returning true, active+toggle → passive`) so the M8 wiring lands
  inside known-tested behaviour.
- **Status bar idempotence over per-slot diffing.** Pi's
  `ctx.ui.setStatus(key, text)` is itself idempotent — writing the
  same string twice is a no-op below the renderer. So
  `recomputeStatusSlots` does the simplest thing: read state, write
  all four slots. That keeps the trigger fan-out (5+ paths) from
  needing per-slot guards or "which trigger fired" plumbing.
- **JSON.parse tolerance in `readCtxThresholds`.** Parsing failures
  do not throw — they fall back to `DEFAULT_CTX_THRESHOLDS`. The
  status bar polls every 1s; throwing on a transiently-malformed
  `models.json` (because the user is editing it) would crash the
  poller and silently freeze the indicator.
- **Auto-open via `pi.on("input")` rather than command interception.**
  Pi's `input` event fires BEFORE command dispatch and BEFORE agent
  processing — so the panel opens passively even when the M6 user
  types `/belmont:auto` (which has no handler yet; that's M8). The
  input watcher checks `event.source === "interactive"` so RPC and
  extension-injected inputs don't trip the auto-open.
- **`MessageRenderer`/`MessageRenderOptions` re-exported now, used
  later.** M8 will register `pi.registerMessageRenderer("belmont.worker",
  …)` to stream worker output. Adding the type re-export now keeps the
  pi/sdk.ts diff for M8 minimal.
- **Ctrl+O lands the flag, not the collapse mechanism.** The brief
  acknowledges this: "Ctrl+O toggles thinking-block visibility globally
  (a session-state flag the message renderer respects)." The status
  bar's `belmont.model` slot reflects the flag immediately
  (`· thinking-collapse` suffix) so the user gets visual confirmation
  the toggle fired; the actual block-collapsing context hook lands in
  M9 alongside lean-ctx.
- **No new knowledge-schema changes.** All pure rule helpers were
  already in place. M6 sits on top of `parseProgress` only.
